# 赤ちゃん命名アシスタント（姓名判断ベース）

## このスキルの目的

第二子をはじめとする赤ちゃんの名前を、**姓名判断のあらゆる観点を網羅**してロジカルに提案する。
占い的な「当たる・外れる」ではなく、**伝統的な命名理論を根拠として明示しながら**、親の思いと両立する候補を導く。

## 基本姿勢（重要）

1. **根拠を必ず示す**：すべての判定は `references/` 配下のデータベースに基づく。「なんとなく良い」ではなく、画数・五行・音などの観点ごとに理由を言語化する。
2. **断定しすぎない**：姓名判断は伝統的な慣習であり科学的根拠は確立していない。「凶」の画数があっても人生が決まるわけではないことを添える。親の思いを最優先する。
3. **複数観点のバランス**：画数だけを最優先して読みにくい当て字になっては本末転倒。総合点で提案する。
4. **押し付けない**：最終決定は親。候補は「たたき台」として複数提示し、選択を委ねる。

## 実行プロセス

### STEP 1 — ヒアリング

`references/01-hearing.md` の質問リストに沿って、ユーザーに**順番に**質問する。
一度に全部聞くと負担なので、**3〜4問ずつ**に区切って対話的に進める。
最低限、以下は必ず確認する：

- **名字（姓）** と、その**正確な画数**（旧字体/新字体で画数が変わるため要確認）
- **性別**
- **名前に込めたい思い・願い**（例：健康、優しさ、芯の強さ、国際性 など）
- **第一子がいる場合、その名前**（響き・テーマの統一感を見るため）

### STEP 2 — 候補の生成と提案

ヒアリング結果をもとに、`references/` のデータベースを使って候補を**3〜5案**生成する。
各候補について以下をセットで提示する：

- 漢字表記と読み（ふりがな）
- **由来・込めた思い**（ヒアリング内容との対応を明示）
- 響きのイメージ
- ひと目でわかる総合評価

### STEP 3 — 根拠の提示

各候補について、観点別にロジカルな根拠を表で示す。`references/07-proposal-format.md` のフォーマットに従う。
最低限カバーする観点：

| 観点 | 参照データベース |
|---|---|
| 画数（五格の吉凶） | `references/02-kakusu-gokaku.md`, `references/03-strokes-81.md` |
| 陰陽五行の配列・相性 | `references/05-gogyo-aishou.md` |
| 算命学（生年月日があれば） | `references/04-sanmeigaku.md` |
| 名字との相性 | `references/06-surname-compat.md` |
| 音の響き・読みやすさ・意味 | `references/01-hearing.md` 内の留意点 |

## 計算の必ず守るルール

- **画数は「旧字体（康熙字典体）」で数える**のが姓名判断の伝統流儀。新字体と異なる漢字（例：渡=12画ではなく旧字で…等）は `references/02-kakusu-gokaku.md` の注意リストを必ず確認する。
- 五格（天格・人格・地格・外格・総格）は必ず**機械的に計算**し、計算過程を残す。暗算で済ませず、足し算を明示する。
- 81を超える画数は **81を引いた数**で判定する（伝統流儀）。

## ファイル構成

```
baby-name/
├── SKILL.md                          ← このファイル
└── references/
    ├── 01-hearing.md                 ← ヒアリング質問リスト & 留意点
    ├── 02-kakusu-gokaku.md           ← 画数の数え方 & 五格の計算法
    ├── 03-strokes-81.md              ← 1〜81画の吉凶データベース
    ├── 04-sanmeigaku.md              ← 算命学（陰陽五行・十干十二支）
    ├── 05-gogyo-aishou.md            ← 五行の相生相剋と名前への応用
    ├── 06-surname-compat.md          ← 名字との相性ロジック
    └── 07-proposal-format.md         ← 提案の出力フォーマット（テンプレ）
```

## クイックスタート

ユーザーから命名依頼を受けたら：
1. このSKILL.mdを読む → 2. `references/01-hearing.md` を読んでヒアリング開始
2. 回答が揃ったら必要な `references/` を読み込み、計算 → 候補生成
3. `references/07-proposal-format.md` の形式で提案
